# 理论/教材类书籍讲解指南

理论/教材类书籍（数学、物理、经济学理论、学术专著）的讲解重点。**先读 `references/explaining-well.md` 的方法，本文件只补充理论类特有的注意点。**

## 讲解要点

1. **从直觉到形式**：先给概念的直觉理解（为什么这么定义、它想捕捉什么现象），再给严格的形式化定义。**避免一上来就扔公式。**
2. **推导必须完整**：涉及公式推导时，一步步展示推导过程，解释每一步的依据，不要跳步（详见 `explaining-well.md` §3.2）。
3. **定义 → 定理 → 证明 → 例子**：对每个重要定理，按这个顺序讲解。证明的**思路**（为什么这样证）和结论同样重要。
4. **概念之间的联系**：主动指出本章概念与前面章节、以及不同概念之间的逻辑关系（五连映射）。

## 直觉与形式化的桥接

理论书最容易"看得吃力的地方"就是直觉与形式之间的鸿沟。讲解时要显式架桥：

- **先问"这个定义想排除什么？"**：很多定义是为了排除病态反例而设计的。讲清"如果没有这条限制，会出现什么怪东西"，定义就变得有动机、可记忆。
- **把符号翻译回人话**：每写一个公式，紧跟一句自然语言翻译（"这个式子其实是在说：任意小的误差范围 ε，都存在一个足够大的 N 使得……"）。
- **画图代替空想**：能用图像/示意说明的（单调性、收敛、区域、相图）就画 ASCII 图或文字结构图。
- **量词逐层拆解**：ε-δ、∀∃ 这类量词嵌套是卡点，要逐层用大白话展开（"先固定 ε，我们再去挑一个 δ，使得……"）。

## 证明策略引导

讲解证明时，不只展示证明步骤，还要解释证明的"设计思路"：

- **为什么选这个证明路径**：是构造法、反证法、归纳法还是对角线法？为什么这个定理适合用这种方法？
- **关键步骤的动机**：证明中某个看似突兀的构造（如选一个特定的 ε、定义一个辅助函数）背后的直觉是什么。
- **常见证明技巧归类**：归纳法（强归纳/普通归纳）、反证法、构造法、ε-δ 语言、不动点定理、对角化。遇到时主动标注技巧名称，帮助用户建立证明工具箱。
- **失败的尝试**：有时可以提一句"如果尝试用 X 方法证明会卡在哪里"，帮助用户理解为什么当前路径是必要的。

## 反例训练

理论理解的关键检验是能否构造反例：

- 每个定理讲完后，追问："如果去掉条件 X，结论还成立吗？请给出反例或说明为什么。"
- 在测验中加入反例构造题：给出一个去掉某个条件的命题，让用户判断真假并构造反例。
- 记录常见的反例模式到 `notes/chNN.md`（如 Dirichlet 函数、Cantor 集、处处连续但无处可微的函数）。

## 符号与术语跟踪

理论书符号密度高，**符号混乱是"看得吃力"的头号原因**。每章维护一个符号表：

- 在 `notes/chNN.md` 中建立"本章符号表"小节。
- 格式：`符号 | 含义 | 首次出现页码`。
- 讲解时遇到新符号，**先解释含义再继续**，不要假设用户记得前章的符号。
- 同一符号在不同章节有不同含义时，主动提醒用户区分（这属于「术语漂移」类误解）。
- 符号表同时**累积进 `books/<slug>/glossary.md`**，保证跨章查找。

## 常见误解清单（理论类）

- **条件遗漏**：用定理时忘了前提条件（如只对紧集成立、只对连续函数成立）。
- **充分必要混淆**：把必要条件当充分条件用。
- **量词顺序**：∀∃ 与 ∃∀ 的区别（"一致连续 vs 连续"）。
- **极限运算交换**：随便交换 lim、积分、求导、求和的顺序。
- **定义域忽略**：在定义域外使用结论。
- **把特例当通例**：由个别例子归纳出错误的一般结论。

## 提问设计（理论类）

- **基础题**：检验定义理解（如"什么是极限的定义？"）
- **推理题**：让用户自己完成一个简单推导或证明
- **概念辨析题**：区分两个易混概念（如"收敛与一致收敛的区别"）
- **反例题**：让用户找出某个命题不成立的反例
- **证明策略题**：给出一个命题，让用户先说出打算用什么证明方法、为什么，再尝试证明
- **翻译题**：给出一个形式化陈述，让用户用自然语言解释它

## 易错点标注

理论书常见的易错点：
- 定义的理解偏差（忽略了某个限定条件）
- 定理适用条件混淆（在不满足条件时误用定理）
- 推导步骤跳步导致的错误
- 符号含义漂移

如果书中包含重要的图、表、示意图，讲解时用文字详细描述其含义，必要时可用 ASCII 图或文字结构图辅助说明。
