# 技术/编程类书籍讲解指南

技术书（编程语言、框架、算法、系统设计）的讲解重点。**先读 `references/explaining-well.md` 的方法，本文件只补充技术类特有的注意点。**

## 讲解要点

1. **概念 → 动机 → 用法**：讲每个技术概念时，按"它是什么、为什么需要它（没有它会怎样）、怎么用它"展开（即 `explaining-well.md` 的因果映射）。
2. **代码示例必须逐行讲**：展示代码时，解释每一行/每一段的作用，不要假设用户能自己看懂。
3. **讲清楚机制而非结论**：例如讲排序算法，要演示排序过程，而不是只给"时间复杂度 O(n log n)"。结论要能从机制推出来。
4. **联系实践**：讲完概念后，给一个贴近真实场景的小例子，帮助用户理解应用场景。
5. **主动对比**：技术概念常常"选型"性质，讲 A 时主动对比 B（如 Redis vs Memcached、乐观锁 vs 悲观锁），并说明各自边界。

## 代码执行验证（必须做）

讲解代码示例时，**用 `bash` 工具实际运行代码**，展示真实输出。不要只给代码不给结果。

- 对于脚本语言（Python、Node.js、Ruby），直接 `bash` 执行。
- 对于编译型语言，先编译再执行。
- 运行结果与书中对比，如有差异，分析原因（版本差异、环境差异、书中笔误）。
- 鼓励用户修改代码参数，观察输出变化，加深理解。

## 常见误解清单

讲解每章时，主动建立"常见误解清单"，记录到 `~/.book-tutor/books/<book-slug>/notes/chNN.md`：

常见误解类型：
- **概念混淆**：如 `==` vs `===`、深拷贝 vs 浅拷贝、同步 vs 异步、进程 vs 线程
- **边界条件遗漏**：空输入、极端值、并发竞态、资源耗尽
- **性能误区**：过早优化、错误的数据结构选择、N+1 查询、不合理的索引
- **作用域/生命周期误解**：变量提升、闭包捕获、内存泄漏、悬垂指针
- **API 误用**：参数顺序记反、返回值类型假设错误、异常未处理

讲解时主动标注这些误解，并在测验中专门考察。

## 手把手拆解的技巧

- **可运行的最小例子**：先给一个能跑起来的最小版本，再逐步加上复杂度，而不是一上来给完整生产代码。
- **每行都问"去掉会怎样"**：对关键代码行，说明删掉它会出什么错，让用户理解每一行的必要性。
- **错误示范**：故意给一段有 bug 或反模式的写法，讲清它错在哪、为什么会踩坑（反例教学）。
- **术语对照**：技术术语中英对照，尤其同一概念在不同生态里叫法不同时要点明（如 "handler / callback / listener"）。

## 提问设计（技术类）

- **基础题**：检验概念理解（如"什么是闭包？"）
- **应用题**：给一个小场景让用户设计解法（如"用你刚学的知识，写一个去重函数"）
- **代码阅读题**：给一小段代码，让用户解释其行为或预测输出
- **Bug 狩猎题**：给一段有 bug 的代码，让用户找出问题并修复。涵盖逻辑错误、边界条件、并发问题等
- **选型对比题**：给两个方案，让用户说明各自的适用场景与权衡

## 易错点标注

讲解时主动标注易错点，格式：`⚠️ 易错：<具体描述>`。在测验中覆盖这些易错点，确保用户真正理解而非死记。
