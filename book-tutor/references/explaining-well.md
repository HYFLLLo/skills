# 讲透一个概念（易懂 · 连贯 · 详细 的操作手册）

本文件是 book-tutor 讲解质量的**操作手册**。SKILL.md 给出原则，这里给出可照着做的方法、模板和反面清单。**每次准备讲解时都应先在脑中过一遍本文件的清单。**

三大目标是**易懂、连贯、详细**；本文件把它们拆成可以逐条打勾的动作。

---

## 一、易懂：先直觉，后命名

### 1.1 直觉优先原则

学生看不懂，几乎总是因为讲解者**先给抽象定义，再给解释**。正确顺序是反过来的：

```
❌ 错误顺序：术语 → 定义 → （勉强）例子 → （太晚了）直觉
✅ 正确顺序：现象/问题 → 直觉/类比 → 术语 → 精确定义 → 机制 → 例子 → 反例
```

### 1.2 类比要从用户熟悉的东西出发

- 优先用 `profile.md` 里用户**已掌握领域**的东西做类比（比如用户是后端工程师，就用请求/缓存/队列做类比）。
- 一个类比讲完，要**点明类比的边界**："这个类比在 X 处会失效，因为……"。没有边界说明的类比会制造新的误解。
- 一个好的类比要能回答：「它像什么？」「它为什么需要存在？」「它和什么容易混淆？」

### 1.3 用「三种说法」讲同一个概念

同一个概念至少换三种说法，覆盖不同类型的理解：

| 说法 | 作用 | 例（以「缓存」为例） |
|------|------|----------------------|
| 生活化 | 建立直觉 | "像书桌上的小书架，把常看的书放到手边" |
| 功能性 | 说明用途 | "用更快的存储保存更慢存储的热数据，减少慢访问次数" |
| 形式化 | 精确、可推理 | "一个 (key → value) 映射，命中时以 O(1) 返回，未命中时回源" |

说三种不是为了啰嗦，而是让不同思维方式的用户都能抓住。

### 1.4 语言层面的可读性

- 长句拆短句；一个句子只说一件事。
- 少用「显然」「易得」「众所周知」——它们只是把困难藏起来。
- 抽象名词第一次出现时，紧跟一个具体例子（"一致性（即：读写任何副本都得到同样的值）"）。
- 用**设问句推进**：「那如果……会怎样？」「为什么不能直接……？」——这能让用户跟着思路走，而不是被灌输。

### 1.5 易懂性自检

- [ ] 每个新概念都先给了直觉/类比，再给术语？
- [ ] 类比都点明了边界（哪里不适用）？
- [ ] 没有出现「显然 / 易得 / 众所周知」而未展开？
- [ ] 抽象名词后面都跟了具体例子？
- [ ] 用户读完这一段的**第一反应**会是"哦原来如此"，而不是"每个字都认识但连起来不懂"？

## 二、连贯：让知识连成网

孤立的知识点最容易被忘掉。每一次讲解都要**把新知识缝进已有的结构里**。

### 2.1 三层连贯

1. **段内连贯**：一段话内部，句与句之间要有因果/递进关系，读起来是一条线，不是并列的碎点。
2. **单元内连贯**：本单元的概念之间要显式连接——"接下来这个，其实是为了解决刚才那个带来的问题"。
3. **跨章连贯**：每讲一节，至少做一次**回指**（"还记得上一章的 X 吗？"）和一次**前瞻**（"这个概念下一章会用来解释 Y"）。

### 2.2 五连映射（每次讲重要概念都走一遍）

| 关系 | 要回答的问题 | 话术示例 |
|------|--------------|----------|
| 先前知识 | 它是前面哪个概念的延伸/一般化/特例/修正？ | "把上一章的 X 从单机推广到分布式，就是它。" |
| 内部结构 | 由哪些部分构成，如何协作？ | "它由三个部分组成：A 负责…，B 负责…，C 负责…。" |
| 因果 | 为什么需要它？没有它会怎样？ | "如果没有它，每次都要重新计算，成本是 O(n)；有了它，摊薄到 O(1)。" |
| 对比 | 容易和谁混淆？边界在哪？ | 做一个两列对照表，逐项比差异 |
| 下游 | 后面哪里会用到它？ | "第 5 章的调度算法会直接用到这里的结论。" |

> 五连映射不需要每次都写满五条，但**因果**和**对比**几乎每次都要有——它们最能防止"背下来了但不会用"。

### 2.3 建立并维护概念地图

- 每章结束后，更新一张**本章概念地图**（文字版即可），画清概念之间的箭头：包含、依赖、因果、对比。
- 章与章之间，用 `state.md` 里的「一句话主线」串起来：每次开新章，先复述上一章的一句话主线。
- 全局层面，维护前面建立的**全书主线预告**，每学完一章就回来更新一句"现在走到哪了"。

示例（文字版概念地图）：

```
信息 →（被加工）→ 知识 →（被应用）→ 智慧
  ↑ 数据是信息的载体；信息是数据的含义
信息系统 ⊃ 硬件 + 软件 + 数据 + 人员 + 流程
  └ 与「信息技术」是整体与手段的关系，易混
```

### 2.4 连贯性自检

- [ ] 本段讲解里，每个"接下来"都能回答"为什么接下来该讲它"？
- [ ] 至少一次回指上一章/上一单元？
- [ ] 至少一次前瞻到后续章节或实际应用？
- [ ] 新概念都挂到了已有的概念地图上？
- [ ] 用户合上笔记，能用一两句话说出"这段在讲什么、它前后连着谁"？

## 三、详细：讲透机制，不跳步

"详细"不等于字多，而是**不留下没解释的跳跃**。

### 3.1 定义要说全四件事

对一个核心定义，回答：

1. **是什么**（精确表述，含术语原文）
2. **为什么需要**（它解决的问题、动机）
3. **怎么运作**（内部机制、组成、流程）
4. **什么时候不适用**（边界条件、反例、限制）

只讲 1 就是"背定义"；讲到 4 才是"懂"。

### 3.2 推导/代码逐步拆解

**公式或证明**：每一步单独成行，并在行末尾标注依据（用了哪个定义、定理、假设）。

```
要证：a² + b² = c² 的推广形式在 n>2 时无正整数解（Fermat）。
Step 1: 假设存在解 (x, y, z)，则由 ... 可得 ...
        依据：整数环上唯一分解（UFD）性质
Step 2: 对等式两边取模 p，得到 ... 
        依据：Step 1 的结果 + 同余的乘法封闭性
...
```

**代码**：逐行解释，每行回答"它在做什么、为什么需要它、去掉会怎样"。

```python
def dedup(items):
    seen = set()          # 用一个集合记录已出现的元素，实现 O(1) 查重
    out = []
    for x in items:       # 线性扫描，保证保序
        if x not in seen: # 已见过就跳过，避免重复
            seen.add(x)
            out.append(x)
    return out
```

### 3.3 详略的判断标准

- **核心概念 / 主线上的概念 / 用户弱项**：写到最细（直觉 + 定义 + 机制 + 例子 + 反例）。
- **次要概念 / 已知领域 / 纯事实**：可精简为一句定义 + 一个例子。
- 判断依据：这个概念**是否被后续内容依赖**、是否出现在 `profile.md` 的弱项里。是则讲厚。

### 3.4 详细度自检

- [ ] 核心定义都回答了「是什么/为什么/怎么运作/何时不适用」？
- [ ] 公式与代码没有跳步，每步都标了依据？
- [ ] 没有用"显然/易得"掩盖推理？
- [ ] 对弱项概念是否讲得比对其他概念更厚？

## 四、例子与反例（每讲必带）

### 4.1 例子要具体、可验证

- 尽量用数字/数据，而不是纯文字描述（"取 n=3 时，结果是 8" 优于 "结果会变大"）。
- 尽量贴近用户的实际场景或已学过的章节。
- 代码类内容要**实际运行**（见 `tech-book.md`），给出真实输出。

### 4.2 反例是检验理解的关键

- 每个重要结论都问一句："去掉某个条件后还成立吗？请举反例。"
- 反例最好能揭示"为什么必须有这个条件"。
- 记录典型反例到笔记，形成用户的"反例库"。

### 4.3 常见误解清单

讲解时主动对照下列类型，发现用户可能踩的就当场点破：

| 类型 | 例 |
|------|----|
| 概念混淆 | 相关 vs 因果；充分 vs 必要；同步 vs 异步 |
| 边界遗漏 | 空输入、极端值、并发、资源耗尽 |
| 因果倒置 | 把结果当成原因；把必要条件当充分条件 |
| 过度推广 | 把特例当通例，忽略定义域/前提 |
| 术语漂移 | 同一术语在不同章节/语境含义不同 |

## 五、讲解前的固定检查清单

每次开口讲解前，快速过一遍：

1. **定位**：这一步在全章/全书主线的什么位置？（先说出"我们接着上次的……"）
2. **直觉**：核心概念的第一句是直觉还是术语？（必须是直觉）
3. **三段**：重要概念走完「直觉 → 定义 → 机制」了吗？
4. **五连**：因果与对比关系点到了吗？
5. **不跳步**：公式/代码每步都有依据说明吗？
6. **例子+反例**：都给了吗？
7. **术语**：新术语有中英对照 + 一句话定义吗？与旧术语的区别点明了吗？
8. **篇幅**：这一单元是否讲得足够厚（核心概念没有一笔带过）？
9. **收口**：有「一句话主线」小结吗？
10. **过载**：本单元是否超过 3 个核心概念？（是则拆分）

## 六、反模式（要避免的讲法）

- **名词轰炸**：一段里抛出多个新术语而不解释彼此关系。
- **结论倾泻**：只给"结论/公式/复杂度"，不讲推导与动机。
- **假详细**：字数很多但都是同义反复，没有信息增量。
- **孤立知识点**：不连接前后内容，用户学完只记得碎片。
- **类比无边界**：用了类比却不说明它在哪失效，反而制造新误解。
- **假装用户懂**：跳过低层基础直接讲高层，用"显然"遮丑。
- **一次讲太多**：一个单元塞 5+ 个概念，导致认知过载。
