# 进度持久化与学习者画像

本文件规定 book-tutor 如何把学习状态落盘、如何在下次会话恢复。**新建或续学任何书时必读。**

## 为什么需要

对话上下文会丢失，但学习是长期过程。所有状态必须写入磁盘，做到：换会话能续学、跨书能复用画像、复习能按时触发、**术语与概念地图能跨会话延续**（这是「连贯」的基础）。

## 数据目录

根目录：`~/.book-tutor/`（Windows 为 `%USERPROFILE%\.book-tutor\`）

```
~/.book-tutor/
├── profile.md                    # 学习者画像（跨书、长期）
└── books/
    └── <book-slug>/
        ├── state.md              # 本书元信息 + 进度 + 复习日程
        ├── glossary.md           # 全书术语表（累积更新）
        └── notes/
            ├── ch01.md
            └── ...
```

### `<book-slug>` 生成规则

- 取书名，转小写，空格与标点替换为连字符
- 中文书名可保留中文（如 `信息系统项目管理师教程-第4版`），也可用拼音缩写
- **同一本书必须始终用同一 slug**。若无法确定是否已存在，先用 `glob` 搜索 `~/.book-tutor/books/*/state.md` 比对书名

> 「章节进度」里的**一句话主线**一列是保证「连贯」的关键：每次开新章前先复述它，用来把记忆接回来。

### `books/<slug>/glossary.md`（术语表，累积更新）

```markdown
# 《书名》术语表

| 术语（中/英） | 白话解释 | 精确定义 | 首次出现 | 易混项 |
|---------------|----------|----------|----------|--------|
| 信息化 / Informatization | 把信息变成生产力 | ... | ch01 §1 | 与「信息系统」不同：前者是过程，后者是实体 |
```

- 每章完成后把新术语**追加**进表，不覆盖历史。
- 「易混项」一列专门记录术语之间的区别，讲解时可据此做对比。

## 读写时机

| 时机 | 动作 |
|------|------|
| 会话开始（新书/续学） | `read` `profile.md`、目标书的 `state.md` 与 `glossary.md`（若存在） |
| 读完书建立结构后 | 创建 `state.md`、`glossary.md` 与 `notes/` 目录 |
| 每章完成后 | 写 `notes/chNN.md`；追加 `glossary.md`；更新 `state.md` 进度表 |
| 每次学习结束 | 更新 `state.md`（进度 + 复习日程）与 `profile.md`（画像） |

## 续学恢复协议

1. `read` `profile.md` → 了解用户节奏、弱项、偏好、已掌握领域
2. `read` `books/<slug>/state.md` → 定位当前章节、复习到期项、上一章「一句话主线」
3. `read` `books/<slug>/glossary.md` → 恢复术语上下文
4. 向用户汇报："上次你学到《X》第 N 章第 M 节，已完成 A 章；上次讲的主线是「____」；复习日程有 K 项到期。这次建议……"
5. 用户确认后从「当前位置」继续，**不要**重头再来

## 合并与冲突规则

- **增量更新**：只改变化的字段，不要整文件重写导致丢失历史（尤其 `profile.md` 与 `glossary.md` 的表格要追加行，不要覆盖）
- **slug 冲突**：若发现同 slug 但书名/来源文件不同，先向用户确认是否同一本书
- **多书并行**：`profile.md` 共享；每本书各自一个 `books/<slug>/`，互不干扰
- **失败兜底**：若写盘失败（权限/路径），告知用户并至少把进度摘要输出在对话里，不要静默丢弃
- **弱项迁移**：某弱项连续两次复习都答对 → 从「弱项与易错概念」移到「已巩固」，保留历史

## 隐私

所有内容仅存本地用户主目录，不上传。不要在文件名或笔记中写入敏感信息。
